# Preventive review — 29 October 2026

Scope: stable v0.4.2 plus the v0.4.3b2 changes, reviewed through authentication, live/module reads, energy integration, settings writes, setup/unload, diagnostics and translations. Changes are published for testing as v0.4.3b3, not a stable release. No live account access or device commands were used during this review.

## Confirmed findings addressed

| Area | Previous failure | Change |
| --- | --- | --- |
| Live URL recovery | Transport/HTTP/auth errors escaped before invalidating the cached URI. | Clear the URI and retry a read once with a fresh URI; refresh authentication once when necessary. Never automatically repeat writes. |
| Offline response shape | A valid disconnected response without `flow` was treated as an expired URI. | Accept explicit connection envelopes, including `con:0`. |
| Energy counters | Offline values and gaps containing missing/nonfinite values could contribute invented consumption or battery energy. | Break integration on offline/invalid samples; require two valid samples within the existing maximum gap. Reject nonfinite saved counters. |
| Measurement availability | Cached module readings remained available indefinitely after polling failures. | Make live measurements unavailable on an explicit disconnect; expire module availability after ten minutes without a successful module response. Daily counters retain their state. This is response-age validation, not proof that the vendor chart's underlying sample is current. |
| Authentication | Argon2 ran in HA's event loop, and concurrent expiry checks could queue redundant logins. | Offload hashing to a worker and recheck token validity under the login lock. |
| Rate limits | The daily login limit contains the word `login` and was classified as invalid credentials. HTTP 429 was a generic connection failure. | Treat limits as temporary failures, honor numeric Retry-After (60 seconds to 24 hours), and pause repeated automatic login attempts. Daily-limit retries wait one hour; the vendor's exact reset timezone is not assumed. |
| Settings lifecycle | Background reads were not tracked/cancelled and results relied on the next live update to appear. | Coalesce background/manual reads, bound the read to 120 seconds once it owns the settings lock, cancel on unload and publish results without falsely marking live data healthy. |
| Settings writes | A queued write could preserve an outdated settings block copied before acquiring the lock. | Build the payload from the latest state while holding the lock; retain reserve-SOC verification and range checks. |
| Mode evidence | Substring matching for `k_1` could accept `k_10`. | Match complete path segments. |
| Malformed settings | Invalid `soc_h` could escape as a conversion error or be silently truncated. | Validate complete integer SOC bounds and report a handled settings error. |
| Chart decoding | Malformed/nonfinite data or explicit device/port conflicts could propagate into the wrong sensor or fail unexpectedly. | Handle malformed charts as connection failures, preserve unknown samples instead of reusing older ones, reject explicit identity conflicts and invalid protobuf field numbers. |
| HTTP error text | aiohttp exception strings can contain signed request URLs. | Use bounded HTTP/type-only messages for transport errors instead of exposing those URLs in the integration's error message. This is not a claim that arbitrary upstream error payloads or exception chains are universally scrubbed. |

## New read-only action

**Refresh battery settings** reads current cloud settings without waiting for the normal 30-minute schedule. It does not send a battery control command. Concurrent requests share the running read. Existing station/entity IDs, history and the energy storage format remain unchanged.

## Node-RED cross-check

Primary implementation inspected: [node-red-contrib-hoymiles-home, commit e48ac860e2d1d17fdad108be4dfe306e511608e2](https://github.com/pinguin45orga/node-red-contrib-hoymiles-home/tree/e48ac860e2d1d17fdad108be4dfe306e511608e2).

- `hoymiles-config.js`: same pre-inspection/Argon2 parameters and response unwrapping; the client explicitly recognizes the daily login limit. Shared credential sessions are a future design reference, not copied into this per-entry client.
- `hoymiles-watch.js`: same consumer `get_sd_uri_c` endpoint and station request; refreshes URLs/re-authenticates after errors and follows server `dly`. Its unlimited retry loop is not copied; this beta bounds an individual read retry.
- The watch node passes through `power`; it does not explain `ems`, `chs` or the relationship between `pv` and `pv2`. Its README describes signed battery power differently from this integration's legacy fallback. That text does not override the maintainer-tested unsigned `power.bat` plus `brs` direction mapping. Signed battery semantics still need per-device validation.
- `hoymiles-modules.js` and `module-data.js` show a concrete future path: read-only `POST /pvmc/api/0/module_data/dmdd_c`, body `{sid, date}`, returning optional gzip-wrapped PlayModuleData protobuf. Available fields include per-inverter temperature/frequency/AC voltage and per-input daily energy. The code identifies micros by ID and aligns arrays with the per-micro time index. This endpoint is not enabled by this beta: obtain an affected-device fixture, verify timestamps/zero-vs-missing semantics and independently test the schema before replacing or extending the proven chart reads.

## Android source check and limits

The [official S-Miles Home download entry](https://m.hoymiles.com/platform/app_balcony) redirects to the Hoymiles download page. Its public `website/json/app_download.json` links Google Play package `com.hm.balcony` and `https://www.pgyer.com/hoymilesBalconyRelease`. The latter advertises v2.13.0, build 2026101400. The APK download returned HTTP 403 in this environment; no APK was downloaded or analyzed. App behavior inferred from third-party implementations is not claimed as direct Android verification.

The manufacturer MQTT guide describes string `ems_mode` and `bat_sts`; it does not prove an enum mapping for the numeric Home-cloud `ems`/`chs` fields. Keep those raw pending manufacturer or repeated app/cloud evidence.

## Validation and remaining work

Local full suite: 29 dependency-free unit tests and 129 HA tests. Eight targeted cases fail against the original v0.4.3b2 API/coordinator/battery code and pass after these corrections. CI additionally runs HACS and Hassfest before publishing the prerelease.

Hardware checks still needed: overnight disconnect/morning recovery; transient live connection failures; settings refresh and an explicitly authorized reserve-SOC change; normal daily energy accumulation. No real-device result is inferred from mocked tests.

Further improvements worth separate validation: shared per-account auth across multiple station entries; background rather than sequential module chart polling; station-local day/time handling when a plant differs from HA's timezone; retries for initially unavailable model metadata; optional bulk inverter telemetry above. Do not guess EMS/charge enums, maximum-power configuration or battery sign conventions merely to expose more controls.
